Sagax 0.5.14 resserre la sécurité des environnements isolés (liens durs, fichier vérifié = fichier ouvert, aucun mot de passe du bureau à distance dans l'environnement des processus), complète l'effacement des données d'une personne selon la Loi 25 et rend visibles les serveurs MCP enregistrés sous un nom maintenant réservé.

## Environnements isolés

* **Liens durs** : `read_file` et `write_file` refusent un fichier qui partage son contenu (lien dur) avec un fichier caché ou un emplacement d'identifiants (`.ssh`, `.git-credentials`...). Un lien dur ordinaire, comme dans un magasin de paquets, passe toujours. Si la liste des autres noms du fichier ne peut pas être établie en entier, la demande est refusée.
* **Fichier vérifié = fichier ouvert** : la lecture, la liste et l'écriture ouvrent elles-mêmes le chemin vérifié, puis confirment que c'est bien le même fichier avant de le lire ou de l'écrire. Un fichier, un lien ou un dossier échangé entre la vérification et l'usage est refusé (« the path changed »).
* **Aucun secret dans l'environnement des commandes** : les commandes ne reçoivent aucune variable secrète. Le bureau à distance de l'environnement ne garde plus ses mots de passe VNC dans l'environnement de ses processus, où une commande pouvait les lire.

**Pour l'opérateur d'un serveur** : le dernier point vit dans l'image des environnements isolés (`deploy/sandbox/Dockerfile`). Reconstruisez cette image avec cette version pour l'appliquer ; une ancienne image fonctionne comme avant, sans ce correctif.

## Loi 25 et niveaux des membres

* **Effacement complet des fils d'une personne** : quand les données d'une personne sont effacées, les fichiers de ses fils ordinaires partent aussi (dossier du fil, exports, gros résultats d'outils, fichiers téléversés ou joints), seulement pour les fils dont elle est propriétaire. Un fichier encore utilisé par un autre fil est gardé.
* **Admin rétrogradé** : un admin qui redevient membre perd tout de suite le niveau Auto de ses bots quand l'organisation ne permet pas ce niveau aux membres. Le niveau revient à Demander et ne peut plus être choisi.
* **Exports personnels privés** : un export fait dans une portée personnelle est déposé seulement dans l'espace Data de cette personne, jamais dans un dossier de fil visible par l'explorateur de fichiers de la console d'admin.

## Sécurité et MCP

* **Noms MCP réservés visibles** : un serveur MCP enregistré par une version antérieure sous un nom maintenant réservé n'est plus ignoré en silence. Réglages, Plugins l'affiche avec un nom libre proposé, **Renommer** et **Supprimer**. Le renommage (réservé aux admins) enregistre le serveur désactivé sous son nouveau nom ; les bots qui l'utilisaient suivent le nouveau nom.
* **Fichier neuf dans le dossier du fil** : créer un fichier qui n'existe pas encore dans le dossier du fil ne demande plus la clé de sécurité. Remplacer ou modifier un fichier existant la demande toujours.
* **Texte tapé destructif** : un texte tapé par un outil (`type_text`, action `type` de l'ordinateur) est lu comme une commande ; une suppression comme `rm -rf ~` est classée destructive.
* **Politique d'outils** : la route de renommage MCP a sa ligne dans la politique d'outils (admin, désactivée par défaut).

## Appels vocaux

* **Allemand et portugais** : la question d'approbation à deux options est maintenant dite en allemand (« Einmal erlauben oder ablehnen? ») et en portugais du Brésil (« Permitir uma vez ou negar? »), plutôt qu'en anglais.

## Installation

**macOS** (Apple Silicon : `arm64`, Intel : `x64`) : ouvrez `Sagax-0.5.14-arm64.dmg` ou `Sagax-0.5.14-x64.dmg` et glissez Sagax dans Applications. Signée (Developer ID) et notariée par Apple.

**Windows** (x64 et arm64) : lancez `Sagax-0.5.14-setup.exe`. Non signé : SmartScreen affiche un éditeur inconnu ; choisissez **Informations complémentaires**, puis **Exécuter quand même**. Versions portables : `Sagax-0.5.14-win-x64.zip` et `Sagax-0.5.14-win-arm64.zip`.

## English

Sagax 0.5.14 tightens isolated environment security (hard links, checked file = opened file, no remote desktop passwords in process environments), completes the erasure of a person's data under Québec's Law 25, and makes MCP servers saved under a now reserved name visible.

* **Hard links**: `read_file` and `write_file` refuse a file that shares its content (hard link) with a hidden file or a credentials location (`.ssh`, `.git-credentials`...). An ordinary hard link, as in a package store, still works. If the file's other names cannot all be listed, the request is refused.
* **Checked file = opened file**: reading, listing and writing open the checked path themselves, then confirm it is the same file before reading or writing it. A file, link or folder swapped between the check and the use is refused ("the path changed").
* **No secrets in the command environment**: commands receive no secret variable. The environment's remote desktop no longer keeps its VNC passwords in its processes' environment, where a command could read them.
* **For a server operator**: that last fix lives in the isolated environment image (`deploy/sandbox/Dockerfile`). Rebuild that image from this version to apply it; an older image works as before, without the fix.
* **Full erasure of a person's threads (Law 25)**: when a person's data is erased, the files of their ordinary threads go too (thread folder, exports, large tool results, uploaded or attached files), only for threads they own. A file still used by another thread is kept.
* **Demoted admin**: an admin who becomes a member again loses Auto on their bots right away when the organization does not allow that level for members. The level returns to Ask and can no longer be chosen.
* **Private personal exports**: an export made in a personal scope is saved only in that person's Data space, never in a thread folder visible to the admin console's file explorer.
* **Reserved MCP names visible**: an MCP server saved by an earlier version under a now reserved name is no longer skipped silently. Settings, Plugins shows it with a suggested free name, **Rename** and **Remove**. Renaming (admins only) saves the server disabled under its new name; bots that used it follow the new name.
* **New file in the thread folder**: creating a file that does not exist yet in the thread folder no longer asks for the security key. Replacing or editing an existing file still does.
* **Destructive typed text**: text typed by a tool (`type_text`, the computer's `type` action) is read as a command; a deletion such as `rm -rf ~` is classed destructive.
* **Tool policy**: the MCP rename route has its tool policy row (admin, off by default).
* **German and Portuguese**: the two-option approval question is now spoken in German ("Einmal erlauben oder ablehnen?") and Brazilian Portuguese ("Permitir uma vez ou negar?") instead of English.

macOS builds are signed with a Developer ID and notarized by Apple. Windows (x64 and arm64, one installer) is unsigned: SmartScreen shows an unknown publisher; choose More info, then Run anyway.
